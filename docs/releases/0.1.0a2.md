# 0.1.0a2: explicit sessions and interactive login repair

This is an engineering alpha, not a production readiness claim. The previous
[0.1.0a1 report](../release-report.md) remains historical evidence. No credentials
from a user report were placed in source, tests or examples; no live account login
was attempted during this repair.

## Behavior changes

- Session.open(name) opens an existing authorized GramFlux session; missing files
  are never created. Saved authorization is checked before context entry.
- Session.create(name) reserves a new named file atomically with O_EXCL; existing
  sessions are never replaced. Reconnecting the same created client reuses its file.
- Session.temporary() stores its key only in process memory; process exit prevents
  local reuse. This does not promise immediate remote authorization revocation.
- A bare Client string/path is now open-only, an intentional alpha behavior change.
  Existing format-version-1 session files remain readable, with no migration needed.
- Session.open(name, require_authorized=False) explicitly resumes an unfinished login.
- Client.login() adds separate bounded phone/code/password input attempts (default 3),
  code-expiry refresh, serialized login calls, and injectable async LoginPrompts.
  Incorrect codes retain the challenge; incorrect passwords do not resend codes.
- Flood waits, network errors, fatal auth errors and cancellation do not enter these
  input retry loops. is_authorized now treats only 401 authorization rejections as
  False; it no longer hides unrelated backend RPC failures as an unauthorized account.
- A NullHandler prevents default backend warnings from interrupting terminal input
  through logging.lastResort. Applications explicitly configuring logging continue
  to receive redacted diagnostics. RPC exceptions remain visible.
- get_me without account authorization explains how to explicitly login/resume.

## Use

```bash
python examples/login.py --create account
python examples/login.py --open account
python examples/login.py --resume unfinished-account
python examples/login.py --temporary
```

Creation/authentication and later reuse are separate operations. See
[sessions](../guides/sessions.md) and [authentication](../guides/authentication.md).
Only explicit application actions prompt for secrets. Default terminal prompts use
worker threads; cancellation cannot interrupt an underlying blocked terminal read.
Use asynchronous UI callbacks where prompt-level cancellation is required.

This version must be built/published and installed before older installations can
use its new APIs; no package-index publication is performed as part of this repair.
