# 0.3.0a2 — hardening and production assessment

Status: **engineering alpha; production approval withheld**. This release hardens the
independent runtime. It is not a claim that the original production definition is met.
The sole direct runtime dependency remains cryptography 50.0.2, with no competing
Telegram client engine or fallback. License remains MIT with dependency notices.

## Implemented changes

- Native update queues enforce both count and uncompressed TL body byte budgets.
  Config.update_queue_bytes defaults to 16 MiB; event_queue_size still bounds count.
  Rejected enqueues do not consume budget. Dequeue releases the byte charge;
  cancellation and shutdown preserve accounting. Overflow closes the connection
  explicitly for later resynchronization rather than silently dropping updates.
- RequestOutcomeUnknown is a TransportError subclass for lost responses or writes
  that may have reached the server. Closed admission before send remains a regular
  TransportError. No ambiguous application request is automatically repeated.
- Heartbeat disconnect timers cover the configured response deadline, the next
  heartbeat interval and a margin, within Telegram's signed-int field boundary.
- Normalized short sent messages preserve the server-provided TTL field.
- CI uses the development lockfile. Added a manual, dedicated-account live workflow
  with read-only, temporary bot authorization and explicit Saved Messages/file modes.
  It does not run automatically for pull requests and never uploads session material.

Byte accounting is **not** a process RSS ceiling: Python objects, an active envelope,
decode/crypto buffers, RPC results and application-owned tasks require additional
memory. Queued charges use decoded/uncompressed wire size, not compressed packet size.

## Verification and its limits

The local source suite and clean installed-wheel checks are recorded in
`research/verification-0.3.0a2.json`. Ruff, formatting, strict mypy, schema verification,
example compilation, wheel/source builds and Twine metadata checks are required.
The dependency scan in `research/dependency-audit-0.3.0a2.txt` reports no known
vulnerabilities; this does not audit protocol glue or prove timing safety.

Six native encrypted loopback load cases submit 1,000 concurrent RPCs per case with a
five-request admission window, for full/intermediate/abridged TCP. Three reverse reply
batches; three close the peer after 11 received requests. All caller tasks settle,
pending correlations clear and reader/socket cleanup completes. Closing can race
reply decoding: outstanding operations fail explicitly instead of returning invented
success. These tests use a controlled peer sharing protocol primitives; they are not
Telegram account tests, fair competitor measurements or a long-duration soak.

The new queue tests cover independent count/byte overflow, exact limits, rejected
admission, dequeue/reuse, cancelled waits and shutdown accounting. Deadline tests
exercise three heartbeat budgets. Existing vector, SRP algebra, malformed-envelope,
update-recovery, session, file-boundary and cancellation tests remain in the suite.

No GRAMFLUX_API_ID/API_HASH/BOT_TOKEN/SESSION configuration was present here.
Consequently real account tests are skipped; no successful phone, password, bot,
message or media operation against Telegram is claimed for this release. Anonymous
DH/ping evidence is reported separately. The live workflow is configured but not
executed remotely. See [live validation](../guides/live-validation.md).

## Production blockers, in priority order

1. **Account interoperability:** execute dedicated user/bot authorization, code and
   2FA, reopen/reuse, messages, unsolicited updates, gap recovery, files and actual
   migration tests. Fix observed failures before approving release scope.
2. **Security review:** independently review RSA_PAD/DH/IGE/SRP and encrypted-message
   processing. Known-answer/negative tests are evidence, not a substitute for review.
   Python bigint timing and the provider's finite-field DH deprecation remain risks.
3. **Reliability scope:** validate sustained real-network operation and interruption
   recovery. Pending RPCs are not automatically replayed. Too-long differences,
   secret-chat/qts, media cross-DC/CDN and resumable transfers remain unsupported.
4. **Durability/operations:** snapshots are not a transactional delivery journal;
   crashes/partial batches may replay callbacks. Session keys remain plaintext at
   rest. Use idempotent handlers and protect backups and host access. POSIX SQLite
   locking is the supported persistent-storage baseline; other platforms need tests.
5. **Key lifecycle:** anonymous destroy_auth_key response confirmation remains
   unverified; EOF is not treated as proof of destruction. Real bot test logout is
   implemented but unverified until a dedicated test bot is configured.

The project keeps its Alpha classifier and prerelease version deliberately. Publishing
stable metadata without closing or explicitly excluding these issues would misstate
the evidence. Nothing has been published or deployed by this work.


## Executed results

The source suite passed **398 tests**, with **6 opt-in tests skipped** and four
FFDH provider deprecation warnings. The complete built-wheel suite passed with the
same totals on Python **3.11.17, 3.12.3, 3.13.16 and 3.14.8**, Linux x86-64.
All four environments imported from site-packages and had no Telethon installed;
the cryptography runtime version was checked explicitly. The source distribution
also installed into a separate clean environment and verified its bundled schema.
The three explicit anonymous Telegram network tests passed (six FFDH warnings).
Strict mypy checked 46 production source files. No Windows/macOS or authenticated
Telegram test success is claimed.

No production runtime workaround or dependency was introduced for this tool issue.
