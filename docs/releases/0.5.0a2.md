# 0.5.0a2 — resumable login checkpoints

Pending user login now survives process exit when using a persistent GramFlux
session. request_login_code commits phone/code-hash metadata alongside the existing
MTProto auth key before returning. PasswordRequired commits a password-stage marker
before reaching application code. Neither login codes nor passwords are stored.

After reopening with Session.open(name, require_authorized=False), sign_in(code=...)
uses the saved challenge. login_challenge also supports the original explicit
sign_in(challenge, code) form. login_stage reports code/password/None after connecting.
Interactive login() follows the saved stage without resending a code. Successful
authorization and expired/invalidated challenges clear the appropriate metadata;
incorrect codes/passwords retain retryable progress.

The additive snapshot field is optional for old session files. Metadata is validated
before mutating restored native state. Existing SQLite transactions and owner-only
permissions apply. Temporary sessions still cannot persist across process death.
Telegram's server-side expiry/revocation remains authoritative. No automatic retry
of ambiguous network failures or parallel authentication flows is introduced.

[Authentication guide](../guides/authentication.md) and
[separate-process example](https://github.com/gramflux/gramflux/blob/main/examples/resumable_login.py).

## Verification

- Source regression suite: 1413 passed, 6 opt-in live tests skipped, 4 existing FFDH
  deprecation warnings.
- Login/lifecycle suites from installed wheels: 44 passed on each of Python 3.11.17,
  3.12.3, 3.13.16 and 3.14.8 on Linux x86-64.
- New tests terminate subprocesses with os._exit, bypassing disconnect and Python
  shutdown, then resume code and password stages with new clients and SQLite handles.
  They verify retained auth-key bytes, no code re-request, hidden sensitive reprs,
  absent stored codes/passwords, error retries, expired-code cleanup, old snapshot
  compatibility and atomic rejection of malformed login metadata.
- Ruff lint/format, strict mypy, schema verification, API inventory, examples
  compilation and staged example CLI parsing passed. Wheel and source archive built.

Telegram backend responses in restart tests are controlled. Real authenticated
Telegram restart interoperability remains unverified; no account credentials were
available. This remains an alpha, with the production blockers documented in
[0.5.0a1](0.5.0a1.md).
