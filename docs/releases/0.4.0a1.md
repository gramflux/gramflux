# 0.4.0a1 — developer-facing operations and events

This release expands the usable Client surface. It remains an alpha: controlled
serialization/event tests do not certify authenticated Telegram interoperability.
The independent MTProto engine and pinned layer 225 remain unchanged in scope.

## Actual public surface

- **23 new high-level operations**, implemented in operations.py and exercised at
  native request/media boundaries: callbacks, inline queries/results, commands,
  typing, reactions, drafts, invites, chat settings, contacts, profile, session
  management, bot start and contact/location/dice messages.
- **8 event classes**: MessageEvent (new and edited variants), RawUpdateEvent,
  DeletedMessagesEvent, ReadHistoryEvent, UserStatusEvent, ChatActionEvent,
  CallbackQueryEvent and InlineQueryEvent. These are routed from accepted native
  updates or actual service messages, not generated aliases pretending to be events.
- Native callback/URL buttons, inline keyboards and text article results. send_message
  accepts native reply_markup and explicit formatting entities. Callback/inline events
  can answer through their bound Client.
- **82 public Client methods in total**: 64 coroutine methods, 17 synchronous methods
  (subscription/removal/stream factories), and one async generator.
  This total is not a count of Telegram operations: it includes registration and
  lifecycle helpers. Generated low-level TL requests are **783**, counted separately.

[The executable inventory](../api-surface.json) is inspected from Client and checked
in CI. Regenerate it with `python -m gramflux.tools.api_inventory --write`; verify
with `python -m gramflux.tools.api_inventory --check`. No declaration is presented
as proof of live usability. The inventory counts Client methods, not constructors,
fields, aliases, filters, or each possible raw update as a separate event.

## Semantics and validation

Typed events use the existing bounded ordered dispatcher, stable per-event priorities,
error isolation, StopPropagation and cancellation-aware counter commit boundary.
Raw subscribers observe accepted Update objects; no synthetic Update wrappers are
invented for difference.new_messages. Message and service/action events still reach
handlers during difference recovery. Unsubscribed derived events avoid queue work.

Non-channel deletion updates do not identify a chat; chat_id remains None. Inline
callbacks retain inline identifiers separately from normal chat/message IDs. Read
snapshots with pts_count=0 may repeat. qts/secret-chat synchronization is still
unsupported. Event reprs omit message/query/callback payloads. Message-oriented
filters fail closed on incompatible typed events rather than raising exceptions.

Chat-title mutations route basic groups and channels to their respective methods;
contacts use InputUser resolution; identifiers, cache times, coordinates, duplicate
inline IDs/commands and invalid invite parameter combinations are validated. Mutations
retain existing timeout/flood/error behavior and are not automatically repeated.
The new domains use native requests and media correlation, not an external bot API.

## Verification

The new focused suites exercise all 23 new operation methods, peer routing, actual
TL request encoding, synthetic response decoding, invalid-input rejection before RPC,
media routing, UTF-8 callback boundaries, native updates through Client dispatch,
callback/inline answers, event isolation, cancellation, duplicate/level snapshots,
service messages and private-data error reporting. These are controlled tests.

Full source and clean-wheel results are recorded in
`research/verification-0.4.0a1.json`. Real-account bot/inline/callback interaction,
profile/chat mutations and unsolicited server-update recovery remain unverified.
Production blockers in [the preceding assessment](0.3.0a2.md) remain applicable;
new convenience methods do not remove the need for real account testing or audit.

See [bot operations and typed events](../guides/bots-and-events.md) and the executable
`examples/bot_events.py`. New ErrorHandler callbacks receive the Event union;
code assuming every event has .message should narrow with isinstance.


## Executed verification results

- **454 passed, 6 skipped, 4 warnings** in the source suite; 56 newly added test cases.
- Same totals from the built wheel in clean Linux environments on Python 3.11.17,
  3.12.3, 3.13.16 and 3.14.8. Imports resolved to site-packages, and Telethon,
  Pyrogram and Hydrogram were absent in all four environments.
- Ruff, formatting, strict mypy (49 production source files), schema and API inventory
  checks passed. Examples compiled. Wheel and source distribution built; Twine strict
  checks passed. A separate source-distribution install verified schema and inventory.
- Six default skips are three account tests and three explicit anonymous network
  probes. These are opt-in and not silently represented as successes. Four warnings
  concern the existing provider's FFDH deprecation.
