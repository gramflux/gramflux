# 0.5.0a1 — complete typed raw function facade

- Adds `client.api`: 783 explicit coroutine methods generated deterministically from
  official layer 225. Keyword argument annotations, required fields, optional flags
  and concrete result unions support editor discovery. Calls use Client.invoke and
  the existing independent native engine; there is no competitor dependency.
- Adds `filters.update_type(...)`: registry-validated selection across all 156 native
  Update constructors, through the existing raw update dispatcher. Secret-chat/qts
  processing remains unsupported. This does not add 156 high-level event classes.
- Adds exhaustive request serialization/forwarding tests, per-constructor selector
  tests, and controlled concurrent lifecycle/flag/cancellation integration tests.
- Extends the checked API inventory to list every async function path and native
  Update constructor. Schema verification now detects any change in the generated
  async facade, as well as constructors and namespaces.

Read [typed API usage](../guides/async-api.md) and inspect [actual surface counts](../api-surface.json).
The 1573 data constructors are not RPC methods: 2356 is the total declaration count,
not the number of usable high-level operations. Existing high-level helpers and
8 event classes remain separate from this raw API facade.

Status remains alpha. This release improves API access, not production certification.
Real authenticated user/bot/media/update interoperability, independent crypto review,
full qts synchronization, automatic DC migration, media CDN support and long-running
fault/soak validation remain release blockers. No throughput superiority is claimed.

## Verification

The source suite and installed wheel suite each passed **1402 tests, with 6
opt-in live tests skipped and 4 FFDH deprecation warnings**. Installed wheels were
tested independently on Linux x86-64 with Python 3.11.17, 3.12.3, 3.13.16 and
3.14.8. All 783 coroutine methods were individually serialized with synthetic
arguments; all 156 Update classes were individually checked against the selector.

Ruff lint/format, strict mypy (51 modules), schema regeneration verification,
API inventory checks, examples compilation, wheel/sdist build and Twine metadata
validation passed. A typed consumer example passed mypy; supplying InputPeerSelf
where InputUser is required was correctly rejected. These are controlled local
results; no authenticated Telegram integration or remote CI run is claimed.
